# Wattle Health — working rules

Read `PRD.md` §4, §7, §8 before touching anything. Contracts live in `src/matching/types.ts`; vocabularies in `disciplines/*.yaml`.

- **Matching is ported from ADHD.ME** (`src/matching`, the finder ranker in `src/demo/clinicians.ts`, `src/finder/filters.ts`, `src/geo/suburbs.ts`); keep provenance comments naming the source file.
- **API keys are allowed (founder 2026-10-24).** Keys live in the environment only (`.env.local`, Vercel env), never in git and never `NEXT_PUBLIC_`. The one model call site is `src/decisions/openai.ts` (OpenAI, `OPENAI_API_KEY`, `OPENAI_MODEL`, default `gpt-5.4-mini`, `store: false`). The patient search (`src/matching`, `src/data/search*.ts`) stays lexical and deterministic: its ranking rules are properties and its tests run without a network.
- **Redaction before the classifier (founder 2026-10-24)**: `classify` and `extractCases` send text through `src/decisions/redact.ts` → `pipeline/redact/redact.py` (patterns, then a Bedrock model in Sydney that only points at spans; code replaces them). It fails closed and is required in production. Default model `amazon.nova-lite-v1:0` (in-region); `REDACT_MODEL=au.anthropic.claude-haiku-4-5-20251001-v1:0` once the AWS account submits the Anthropic use-case form. Places (suburb, city, state) are kept for matching. Debug log: `REDACT_LOG=path` (redacted text + input hash only, never the input). Eval: `python3 pipeline/redact/eval/run_eval.py [--downstream]`; `--downstream` compares OpenAI decisions on original vs redacted against a rerun-noise baseline. `redact: false` on `/api/decisions/classify` is the eval baseline and needs the API key.
- **The decisions loop** (`src/decisions`, `/admin`, `/api/decisions/*`): every category is scored 0..1 with no weighting; a decision tree trained on the founder's case studies makes the decision and learns which parameters matter; a second pass queues what no category covers for human review; an approved candidate becomes a category the classifier outputs next time, and the next training run can split on it. Vocabulary categories are edited in `disciplines/mvp.yaml`, reviewed ones in `/admin`. Transcripts are never stored (runs keep a SHA-256); case studies live in the decisions store, never in git. `/admin` needs `ADMIN_PASSWORD`; outside tools send `Authorization: Bearer $DECISIONS_API_KEY`. Tests stub the model.
- **No emails.** Outreach is a founder action and is not drafted here.
- **Three tiers, three badges**: register / declared / found, each with a date. "Not declared" is a rendered value, never a blank.
- **Personal profiles come in four statuses**: `published` (the doctor's own words from their practice website, source URL on the record; 122 QLD doctors in `data/enriched/personal/research-*.json`, incl. 6 healthspan doctors with `healthspan.evidence` from their own pages), `doctor-approved` (the /join flow), `illustrative` (fictional, `synthetic: true`, off by default, labelled everywhere) and `draft` (reads as no profile). Never paraphrase a review into a profile.
- **The ADHDme network is generated, not hand-edited** (2026-10-24): `pipeline/adapters/adhdme.py` writes `data/adhdme/clinicians.json` and `data/enriched/personal/research-adhdme*.json` from the ADHDme site's `CLINICIANS`; hand-researched words live in `data/adhdme/personal.json`. Run it with `--check` after touching either repo. `reach` says which states a provider sees people in; never mark a prescriber national.
- **Modes** (`src/mode.ts`): `wattle` (everything) and `adhdme` (ADHD support only: the ADHD cohort, ADHD copy, no Healthspan or Discover, off-topic searches answered with a note). Cookie `wattle.mode`, default `NEXT_PUBLIC_APP_MODE`, `?mode=` sets it. Server code reads it with `currentMode()`; anything that lists providers goes through `scopeRoster()`.
- **No default place**: a search with no place named covers all of Australia. Never fall back to Brisbane.
- **Deploy target is Vercel only.** No static export, no GitHub Pages, ever (founder decision 2026-10-16).
- **Text budget**: 20 to 60 words per whole screen at 390 px, including header and footer chrome. Measure with `node qa/iphone/words.mjs` (no build gate exists yet).
- **Reviews (founder decision 2026-10-18)**: only verified patient reviews written in Wattle (`/api/reviews`, `supabase/migrations/0005_patient_reviews.sql`), held as pending until a person approves them, with clinical-outcome claims and medicine names removed (National Law s133). Never import or scrape a review. Exception (founder 2026-10-18, demo platform): generated demo reviews from `src/data/demo-reviews.ts`, built only from the doctor's own published themes, labelled "Demo reviews, not real patients" wherever shown, never once real reviews exist, off with NEXT_PUBLIC_DEMO_REVIEWS=0. The amalgamated "What patients say" is lexical (`src/data/review-themes.ts`).
- **Copy**: no testimonials in marketing copy, no superlatives, "specialist" outside an Ahpra specialty, medicine brand names. (checked by hand; no build gate exists yet).
- **Design system (Apple pass, 2026-10-23, `docs/apple/PLAN.md`)**: colours, the iOS type ramp (`text-large-title` … `text-caption2`, `text-quote`, `text-hero`), radii and motion are tokens in `app/globals.css`; screens compose `src/ui/kit` (NavBar, LargeTitle, Group, Cell, GroupHeader, Segmented, Button, Toggle). No raw `text-[Npx]`, hex colours, uppercase eyebrows or new keyframes in screens; every target is 44 px (Apple-sized controls use `.hit`). Check with `node qa/apple/audit.mjs` and `node qa/apple/behaviour.mjs`.
- **Ranking rules are properties, not examples**: `src/matching/*.properties.test.ts` uses fast-check.
- Stack: Next.js 15, React 19, TypeScript strict, Tailwind 4, vitest, fast-check, pnpm. Newsreader display over Inter. Dev server port 3300.
- Commit to main and push after every meaningful change.
